# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FirewallDuty is a Unity 6 (editor `6000.4.6f1`) first-person game aimed at mobile (touch controls, Android bundle settings, `Mobile_RPAsset`/`PC_RPAsset` URP pipelines in `Assets/Settings/`). It uses URP 17, the new Input System package (`activeInputHandler: 1`, Input System only — the legacy `UnityEngine.Input` API will throw), and `com.unity.ai.navigation`.

There is no CLI build/test/lint workflow. Work happens in the Unity Editor; builds go through File > Build Profiles. The `.sln`/`.csproj` files are generated by Unity and gitignored (see `ignore.conf`), so don't edit them. No test assemblies or `.asmdef` files exist; all scripts compile into `Assembly-CSharp`.

Version control is Plastic SCM (`.plastic/`, `ignore.conf` is its ignore file), not git.

## Where the game code lives

Only `Assets/Scripts/` is first-party code (~280 lines). Everything else under `Assets/` is third-party asset-store content (`ithappy/`, `PolygonalMind/`, `Mnostva Art/`, `PandazoleHome/`, `nappin/`, `TV LED 30¨/`, `TextMesh Pro/`, `TutorialInfo/`) — leave it alone unless asked. `Assets/ithappy/Casino_Free/Scripts` contains its own character controller and editor tooling that the game scripts do **not** depend on. `Assets/_Recovery/` holds Unity auto-recovered scenes, not live content.

## Scenes

`Assets/Scenes/Company_scene.unity` is the scene that uses the game scripts. `Bank_scene` and `SampleScene` exist too, but only `SampleScene` is currently in Build Settings (`ProjectSettings/EditorBuildSettings.asset`), so add `Company_scene` there before making a build that should include it.

## Architecture

A mobile first-person controller plus a raycast interaction system. The pieces are wired together in the scene through serialized fields (not code lookups), so check `Company_scene.unity` when behavior seems unconnected:

- **Input (UI-driven, not Input System actions):** `VirtualJoystick` and `TouchLookArea` are uGUI `IPointerDown/Drag/Up` handlers. `VirtualJoystick.Direction` is a normalized `Vector2` exposed as a property. `TouchLookArea.OnDrag` forwards `eventData.delta` to `PlayerMobileController.ApplyLookDelta`.
- **Movement:** `PlayerMobileController` (requires a `CharacterController`) polls `VirtualJoystick.Direction` each `Update` for movement relative to the player transform, and applies gravity manually. `ApplyLookDelta` yaws the player root and pitches only the camera transform (clamped).
- **Interaction:** `PlayerInteraction` picks a target every `Update`: first the crosshair raycast (`interactionDistance`), then the nearest `Interactable` within its own `InteractionRange` with line of sight (so a prompt shows when walking up to a door without aiming). Targets are found via `GetComponentInParent`, so colliders can be on child objects. It exposes `CurrentInteractable`; its public `Interact()` calls `Interactable.Interact(Transform interactor)` and is hooked to the on-screen button's `OnClick` in the scene.
- **Prompt button:** `InteractionPromptUI` sits on that Button, shows or hides it with a `CanvasGroup` (the component must stay active), and sets the label from `Interactable.PromptText`.
- **Interactables:** subclass `Interactable` and override `Interact()` (or `Interact(Transform)` if the player's position matters) and optionally `PromptText`. `DoorInteractable` toggles `doorPivot` around parent-space Y; the pivot's origin must be the hinge. With `SwingDirection.AwayFromPlayer` it works out the swing side from the hinge and the leaf's closed position.
- **Door gotchas:** a door leaf must not be Static (Batching Static meshes ignore transform changes), and frame prefabs may carry a full-doorway `BoxCollider` that blocks the player after the door opens. `Tools > Firewall Duty > Set Up Doors In Open Scenes` (`Assets/Scripts/Editor/DoorSetupTool.cs`) fixes both, adds `DoorInteractable` to every door-named object, and wires the prompt button. It is idempotent. `Tools > Firewall Duty > Run Door Self-Test` checks the logic on throwaway objects.
